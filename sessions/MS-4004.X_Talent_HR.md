**Base module:** MS-4004.X HR module + Researcher
**Primary tool:** Microsoft 365 Copilot (desktop / work experience)
**Company world:** Acme Bottling — the same packaging business used across the curriculum. The role you'll hire for (a Logistics Coordinator) plugs into the same Supply Chain team and people from the other sessions, so the world stays consistent if you take more than one.

In this lab you'll use Microsoft 365 Copilot to handle the everyday HR jobs that eat time: turning a role description into a fair interview guide, building a 30-60-90 onboarding plan from rough notes, recommending a learning path from a skills gap, and drafting a change message people actually read. You'll finish with a reusable prompt library and a validation habit for anything sensitive.

> **Ground rules for this lab**
> - Copilot works from the **files you give it** — it is not connected to your HRIS, ATS, or LMS here.
> - Use only the **dummy/sanitized data** provided. Never paste real employee or candidate data.
> - Copilot **drafts and organizes** — a human reviews anything that affects a person's hiring, pay, or standing.
> - Any "agent that screens candidates" or "auto-onboarding bot" idea is **future-state** — we note it, we don't build it today.

## Exercise 1: From a role description to a fair interview guide

**Scenario:** Acme Bottling is hiring a **Logistics Coordinator** for the Midwest DC. You need a fair, consistent interview guide today, built straight from the role — not from memory.

### Task 1 — Set your HR voice and get oriented (8 min)

1. First, tune Copilot for HR work. In **Copilot Chat** settings, add a **custom instruction**:

   ```
   When I work on HR content: write in plain, inclusive English. Keep bias out of hiring
   language, avoid jargon, and make drafts easy for a stakeholder to edit. For anything
   sensitive (hiring, performance, pay, personal data), add a short note on what a human
   must review before it's used.
   ```

2. Start the **Researcher** agent and attach **`role_description.docx`**.
3. Get oriented by pulling out what the role really tests for:

   ```
   Using ONLY the attached role description, identify the 5–6 core competencies this role
   is really testing for. For each, note must-have vs nice-to-have and why it matters.
   List anything vague that should be clarified before we interview.
   ```

4. Jot down the competencies — they're the backbone of the guide.

### Task 2 — Build the structured interview guide (10 min)

1. Still in Researcher, build the guide:

   ```
   Create a structured interview guide from those competencies. For each: one behavioral
   question, one follow-up probe, and a simple 1–3 scoring rubric with what "strong" vs
   "weak" looks like. Keep questions job-related and free of bias. Add a short intro
   script and a closing that invites candidate questions.
   ```

2. Review for fairness: is every question tied to the job? Remove anything that drifts into personal territory.

### Task 3 — Turn the interview approach into a reusable prompt (10 min)

1. Make that one-off into a **template** you can reuse for any role:

   ```
   Rewrite the interview-guide prompt above as a reusable template with [placeholders]
   for [ROLE DESCRIPTION] and [NUMBER OF COMPETENCIES]. Keep it short enough to paste in
   under a minute.
   ```

2. Save it to the **Prompt Library** (Copilot Chat → **Prompts** → save), and start a scratch doc titled **"Acme HR Prompt Library."**
3. Test it: point the template at a different role line and confirm it still produces a fair, structured guide.

### Task 4 — Validation checkpoint (7 min)

In your scratch doc, answer for this guide:

- **Source:** Which file did Copilot use? Did it stay inside it?
- **Assumptions:** Did it invent any requirement not in the role description?
- **Risk:** What's the harm if a biased or off-topic question slips through?
- **Human review:** Who signs off before this is used with a real candidate?

> **Exercise 1 output:** a fair interview guide + a reusable interview-guide prompt saved to your library.

## Exercise 2: Onboarding, learning, and people communications

**Scenario:** The hire is made. Now you need an onboarding plan from a manager's messy notes, a learning path to close the new hire's skills gap, and a clear announcement for a change that's coming — a new order-tracking dashboard.

### Task 1 — Turn messy notes into a 30-60-90 onboarding plan (10 min)

1. Open **`onboarding_scenario.docx`** — it's deliberately rough (systems, people, early wins, and a TBD gap).
2. In **Copilot in Word** (or Chat, then paste into Word):

   ```
   Turn the notes below into a clean 30-60-90 day onboarding plan for a new Logistics
   Coordinator. Organize into three phases with: goals, access/systems to set up, people
   to meet, and the expected "early win" for each phase. Flag anything marked TBD or
   unclear as an open item to confirm with HR — do not invent policy details. Notes: [PASTE]
   ```

3. Confirm Copilot flagged the **week-1 compliance training "TBD"** as an open item instead of inventing one.

### Task 2 — Turn a skills gap into a learning path (10 min)

1. Open **`skills_list.csv`** in **Excel** and skim current vs target levels and priorities.
2. In **Copilot in Excel** (or attach the CSV in Chat):

   ```
   Using ONLY this skills list, recommend a prioritized 90-day learning path. Focus first
   on High-priority gaps with the biggest level difference. For each, suggest a practical
   way to build the skill (on-the-job task, short course, or mentor pairing) and a simple
   way to tell it's improving. Keep it realistic for someone also doing a full-time job.
   ```

3. Sanity-check: does it lead with the High-priority, biggest-gap items (order-tracking, Excel analysis, data-quality habits, Copilot basics)?

### Task 3 — Draft and adapt the change communication (10 min)

1. Open **`employee_comm_brief.docx`** — read the change, the audience tone notes, and the structure to match.
2. In **Copilot in Word**, generate the message:

   ```
   Draft an employee change-announcement using the brief below. Match this structure:
   1) What's changing (1–2 sentences), 2) Why it helps you, 3) What we need from you,
   4) Timeline & support, 5) Where to ask questions. Tone: warm, plain, no jargon;
   acknowledge people are busy and change-weary. Under 200 words. Brief: [PASTE]
   ```

3. Then practice reuse across channels — and save this as a prompt:

   ```
   Turn the announcement into two short versions: (a) manager talking points for a team
   huddle, and (b) a 3-line Teams channel post with a clear call to action. Keep the
   meaning identical; just fit each channel.
   ```

4. Save an **Employee communication** prompt to your library.

### Task 4 — Validation checkpoint and save the library (10 min)

1. Run the four-question check (**Source / Assumptions / Risk / Human review**) on the onboarding plan, learning path, and all comms.
2. Confirm your **Acme HR Prompt Library** holds **4–5 reusable prompts**:
   - Interview guide (Exercise 1)
   - Onboarding plan
   - Learning-path recommendation
   - Change-management communication
   - Multi-channel comms adaptation
3. Paste everything — objectives, your prompts, and validation notes — into a single Markdown file (next section).

> **Exercise 2 output:** an onboarding plan, a learning path, a change announcement in three formats, and a 4–5 prompt library.

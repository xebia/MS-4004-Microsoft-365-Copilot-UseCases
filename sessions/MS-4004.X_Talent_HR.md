# MS-4004.X — Talent / HR Hands-On Lab
### Acme Bottling · Microsoft 365 Copilot

**Audience:** Talent and HR team members — recruiters, HRBPs, L&D, people ops — who already use Copilot and want to move faster on hiring, onboarding, and employee comms.

**Format:** ~60 minutes of hands-on

**Level:** Intermediate. We skip the basics and get straight into real Acme Bottling work.

You're hiring a **Logistics Coordinator** for Acme's Midwest DC. You'll build a fair interview guide, onboard the hire, and announce a change people actually read.

> **How to use this lab:** Just read and follow along. Nothing to install, no repo to download, no code to save. Open the files linked below and go.

---

## What you'll be able to do

- Turn a role description into a structured, bias-checked interview guide.
- Build a 30-60-90 onboarding plan from rough, unstructured manager notes.
- Turn a skills gap into a prioritized, realistic learning path.
- Build reusable prompts for interview guides, onboarding, learning paths, and comms.
- Keep a validation habit so nothing affecting a person's job goes out unreviewed.

## Learning arc

This lab moves in one direction: **hire fairly, then set the person up to succeed.**

|  | **Exercise 1 — From role description to a fair interview guide** | **Exercise 2 — Onboard and communicate** |
|---|---|---|
| **You're doing** | Building a hiring instrument | Building the new hire's first 90 days |
| **Copilot's job** | Extract competencies, draft questions and rubric | Structure messy notes, prioritize gaps, draft comms |
| **Your job** | Decide what's job-related and fair | Decide what's policy and what's still TBD |
| **Stakes** | External — a real candidate is scored on it | External — a new hire and a whole team read it |
| **You leave with** | A defensible interview guide | Three people-facing artifacts + a 4-prompt library |

Every task runs the same beat: **prompt → read it critically → keep what's reusable.**
Every exercise ends the same way: **Source / Assumptions / Risk / Human check.**

## What this means when it affects someone's job

In HR the stakes are a person's hiring, pay, or standing. Copilot drafts and organizes; a
human reviews anything that touches a person's job — including the bias check, which is
yours to make, not Copilot's. Every exercise ends with source, assumptions, risk, and who
signs off.

# Exercise 1 — From a role description to a fair interview guide

**Objective:** Build an interview guide where every question maps to a competency in the
requisition, with a scoring rubric and a bias pass applied.

**Scenario:** Acme Bottling is hiring a **Logistics Coordinator** for the Midwest DC. You
need a fair, consistent interview guide today, built straight from the role — not from
memory.

### Task 1 — Set your HR voice and unpack the role

First you'll tell Copilot how to write for HR, then pull the competencies out of the req.

1. Open **Copilot Chat** and go to **Settings** (gear icon or your profile picture, top
   right) → **Personalization**.
2. Add this **custom instruction** and save:

   ```
   When I work on HR content: write in plain, inclusive English. Keep bias out of hiring
   language, avoid jargon, and make drafts easy for a stakeholder to edit. For anything
   sensitive (hiring, performance, pay, personal data), add a short note on what a human
   must review before it's used.
   ```

   *No Personalization option in your tenant? Paste this block at the top of your first
   prompt in each exercise instead.*
3. In Copilot Chat, open **Agents** in the left sidebar (or the agent picker above the
   prompt box) and select **Researcher**.
4. Attach `AcmeBottling_Role_Description.docx` using the paperclip icon next to the prompt
   box.
5. Paste this prompt and press Enter:

   ```
   Using ONLY the attached role description, identify the 5–6 core competencies this role
   is really testing for. For each, note must-have vs nice-to-have and why it matters.
   List anything vague that should be clarified before we interview.
   ```

6. Jot down the competencies — they're the backbone of the guide.

> **Why this matters:** Competencies come from the requisition, not from memory. That's
> what makes the guide consistent across every candidate and defensible later.

### Task 2 — Build the structured interview guide

1. Stay in the same Researcher chat and paste:

   ```
   Create a structured interview guide from those competencies. For each: one behavioral
   question, one follow-up probe, and a simple 1–3 scoring rubric with what "strong" vs
   "weak" looks like. Keep questions job-related and free of bias. Add a short intro
   script and a closing that invites candidate questions.
   ```

2. Read it once for structure: does every competency have a question, a probe, and a rubric?

### Task 3 — Pressure-test the guide for bias

1. In the same chat, make Copilot audit its own output:

   ```
   Review the interview guide you just wrote. For each question, state which competency
   from the role description it tests. Flag any question that is not clearly tied to the
   role, that could touch age, family status, health, national origin, or personal life,
   or that a candidate without insider knowledge couldn't answer. Suggest a replacement
   for each one you flag.
   ```

2. Remove or rewrite anything flagged. **This is a first pass, not an approval** — a human
   still owns the final read.

### Validation checkpoint

In a scratch doc, answer for this guide:

- **Source:** Which file did Copilot use? Did it stay inside it?
- **Assumptions:** Did it invent any requirement not in the role description?
- **Risk:** What's the harm if a biased or off-topic question slips through?
- **Human check:** Who signs off before this is used with a real candidate?

> **Exercise 1 output:** a competency-mapped, bias-checked interview guide you could hand
> to any panel member.

# Exercise 2 — Onboard and communicate

**Objective:** Produce a 30-60-90 plan with every unknown flagged rather than invented, a
prioritized learning path, and a change message that works in three channels.

**Scenario:** The hire is made. Now you need an onboarding plan from a manager's messy
notes, a learning path to close the new hire's skills gap, and a clear announcement for a
change that's coming — a new order-tracking dashboard.

### Task 1 — Turn messy notes into a 30-60-90 plan

1. Open `AcmeBottling_Onboarding_Notes.docx` in **Word** — it's deliberately rough
   (systems, people, early wins, and a TBD gap). Copy the notes.
2. Create a new **Word** document, and on the **Home** tab click the **Copilot** button.
3. Paste this prompt, replacing `[PASTE]` with the notes you copied:

   ```
   Turn the notes below into a clean 30-60-90 day onboarding plan for a new Logistics
   Coordinator. Organize into three phases with: goals, access/systems to set up, people
   to meet, and the expected "early win" for each phase. Flag anything marked TBD or
   unclear as an open item to confirm with HR — do not invent policy details. Notes: [PASTE]
   ```

4. Confirm Copilot flagged the **week-1 compliance training "TBD"** as an open item
   instead of inventing one.

> **Why:** Inventing a policy detail is the single most damaging thing Copilot can do in
> HR. "Flag, don't invent" is the instruction that prevents it.

### Task 2 — Turn a skills gap into a learning path

1. Open `AcmeBottling_Skills_List.csv` in **Excel** and skim current vs target levels and
   priorities.
2. On the **Home** tab, click the **Copilot** button, then paste:

   ```
   Using ONLY this skills list, recommend a prioritized 90-day learning path. Focus first
   on High-priority gaps with the biggest level difference. For each, suggest a practical
   way to build the skill (on-the-job task, short course, or mentor pairing) and a simple
   way to tell it's improving. Keep it realistic for someone also doing a full-time job.
   ```

3. Sanity-check: does it lead with the High-priority, biggest-gap items (order-tracking,
   Excel analysis, data-quality habits, Copilot basics)?

### Task 3 — Draft the change communication, then fit it to each channel

1. Open `AcmeBottling_Employee_Comm_Brief.docx` in **Word** — read the change, the
   audience tone notes, and the structure to match. Copy the brief.
2. Create a new **Word** document, click **Copilot** on the **Home** tab, and paste this
   prompt, replacing `[PASTE]` with the brief:

   ```
   Draft an employee change-announcement using the brief below. Match this structure:
   1) What's changing (1–2 sentences), 2) Why it helps you, 3) What we need from you,
   4) Timeline & support, 5) Where to ask questions. Tone: warm, plain, no jargon;
   acknowledge people are busy and change-weary. Under 200 words. Brief: [PASTE]
   ```

3. Then adapt it without changing the meaning — paste this next:

   ```
   Turn the announcement into two short versions: (a) manager talking points for a team
   huddle, and (b) a 3-line Teams channel post with a clear call to action. Keep the
   meaning identical; just fit each channel.
   ```

### Task 4 — Save your prompt library

1. Create a new **Word** doc titled **"Acme HR — Prompt Library"**.
2. Paste in the four prompts from the
   [Prompt Library](#prompt-library-your-leave-behind) section below.
3. Save it somewhere you'll actually find it again.

This is your leave-behind. Swap in the next req or the next change and reuse.

### Validation checkpoint

- **Source:** Did the plan, path, and message each stay inside the file you gave Copilot?
- **Assumptions:** Did Copilot invent a policy, a benefit, a date, or a training requirement?
- **Risk:** What's the harm if a new hire follows an invented policy detail on day one?
- **Human check:** Who signs off before this reaches the hire and the wider team?

> **Exercise 2 output:** a 30-60-90 onboarding plan with open items flagged, a prioritized
> learning path, a change announcement in three formats, and a 4-prompt library.

## Prompt Library (your leave-behind)

Save these four. Fill the `[placeholders]` each time.

**1. Interview guide**
```
Using ONLY [ROLE DESCRIPTION], identify the core competencies, then build a structured
interview guide: one behavioral question, one follow-up, and a 1–3 rubric per competency.
Keep questions job-related and bias-free. Add an intro script and a closing. Then map
each question to its competency and flag anything not clearly tied to the role.
```

**2. Onboarding plan**
```
Turn the notes below into a [30-60-90 / TIMEFRAME] onboarding plan: goals, systems/access,
people to meet, and an early win per phase. Flag anything TBD as an open item to confirm —
do not invent policy. Notes: [PASTE]
```

**3. Learning-path recommendation**
```
Using ONLY [SKILLS FILE], recommend a prioritized [TIMEFRAME] learning path. Lead with
high-priority, biggest-gap skills. For each: a practical way to build it and a simple
progress signal. Keep it realistic alongside a full-time role.
```

**4. Change communication (and channel adaptation)**
```
Draft an employee change announcement from the brief below. Structure: what's changing,
why it helps you, what we need from you, timeline & support, where to ask questions.
Tone: warm, plain, no jargon, under [WORD COUNT]. Brief: [PASTE]
Then adapt it into [FORMATS, e.g., manager talking points + a 3-line Teams post], keeping
the meaning identical.
```

## Facilitator notes

- **Data hygiene:** Reinforce the sanitized-data rule up front — HR is the session where
  someone is most tempted to paste a real résumé or a real employee record. Don't.
- **HR reality:** The teachable moment is Ex.2 Task 1. If anyone's onboarding plan filled
  in the compliance-training TBD with a made-up policy, stop and show the room — that's
  exactly the failure mode the "flag, don't invent" instruction prevents. Ex.1 Task 3 is
  a first-pass bias filter, never an approval.
- **Capture agent ideas:** If someone imagines "an agent that screens candidates" or an
  "auto-onboarding bot," that's a real agent opportunity — capture it and route to
  **Chris Bartlow**. Keep this lab current-state Copilot.
- **Timing:** Each exercise is about half the hands-on time. Fast groups can rerun the
  Ex.1 prompts against a different Acme role, or adapt the Ex.2 announcement for a
  frontline DC audience versus a corporate one.

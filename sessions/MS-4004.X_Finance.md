# MS-4004.X — Finance Hands-On Lab
### Acme Bottling · Microsoft 365 Copilot

**Audience:** Finance team members — analysts, accountants, FP&A, and finance managers —
who already use Copilot and want to move faster from raw numbers to a reviewed story.
**Format:** ~60 minutes of hands-on (up to ~75 if your group goes deep), inside a
~90-minute session.
**Level:** Intermediate. We skip the basics and get straight into real Acme Bottling work.

Month-end just closed. You'll take an actuals export, find what moved and what looks
wrong, QA a messy AR aging sheet, and turn it into a memo and a slide your CFO can act on.

> **How to use this lab:** Just read and follow along. Nothing to install, no repo to
> download, no code to save. Open the files linked below and go.

---

## What you'll be able to do

- Analyze budget vs actual to find variance drivers, anomalies, and missing values.
- QA a messy spreadsheet — bad dates, wrong buckets, negative or blank amounts.
- Draft a finance memo that separates confirmed facts from estimates.
- Build reusable prompts for variance analysis, spreadsheet QA, memos, and briefing slides.
- Keep a validation habit so no unverified number reaches leadership as fact.

## Learning arc

This lab moves in one direction: **trust the numbers, then tell the story.**

|  | **Exercise 1 — From actuals to a reviewed story** | **Exercise 2 — QA the data, then write for leadership** |
|---|---|---|
| **You're doing** | Finding drivers and anomalies | Cleaning data, then writing for the CFO |
| **Copilot's job** | Analyze, flag, question its own output | Draft to a structure, label estimates |
| **Your job** | Decide which flags are real | Decide which numbers are safe to state |
| **Stakes** | Internal — only you see it | External — the CFO and regional GMs see it |
| **You leave with** | A variance and anomaly list you can defend | A memo, a slide, and a 4-prompt library |

Every task runs the same beat: **prompt → read it critically → keep what's reusable.**
Every exercise ends the same way: **Source / Assumptions / Risk / Human check.**

## The one rule to protect

**Copilot assists. A human validates.** In Finance the control matters as much as the
answer. Every figure Copilot produces is an estimate until a person confirms it — so
every exercise ends with source, assumptions, risk, and who signs off.

# Exercise 1 — From monthly actuals to a reviewed story (about 30 min)

**Scenario:** Month-end close just finished. Your CFO, **Dana Whitfield**, wants the August
variance story before tomorrow's leadership sync — what moved, why, and what needs a
decision. You have the actuals export; you don't yet trust every number in it.

### Task 1 — Set your finance voice and get oriented in Excel (8 min)

1. First, tune Copilot for this work. In **Copilot Chat** settings, add a **custom
   instruction**:

   ```
   When I work with finance data: be precise and controls-first. Lead with the headline
   number and the biggest driver. Always separate confirmed facts from estimates, label
   anything unverified as "estimate pending review," and end with the assumptions you
   made and what a human should verify. Use plain English, no jargon.
   ```

   This single step changes the tone of everything below — you'll see Copilot flag its own
   assumptions without being asked each time.

2. Open `AcmeBottling_Finance_Monthly_Actuals.xlsx` in **Excel**. Note the two tabs: *Aug 2026 Actuals*
   and *YTD by Region*.
3. Open **Copilot in Excel** (Home tab → **Copilot**). Make sure the range is a table
   (`Ctrl+T`), then paste:

   ```
   Give me a quick overview of this actuals table: columns, number of rows, total budget
   vs total actual revenue, and the overall variance %. Then list any rows where the
   Actual Revenue is blank or the Notes column is filled in.
   ```

4. Jot down what Copilot flags — you'll dig into those next.

> **Why this matters:** You're establishing the shape of the data before you ask it for
> conclusions. Skip this and you can't tell a real anomaly from a formatting artifact.

### Task 2 — Use Analyst to find variance drivers and anomalies (10 min)

1. Open **Copilot Chat**, start the **Analyst** agent, and attach `AcmeBottling_Finance_Monthly_Actuals.xlsx`.
2. Run this analysis prompt — note it **defines what counts as an exception** so results
   are repeatable:

   ```
   Using ONLY the attached actuals file, analyze budget vs actual. Do three things:
   1) Identify the 3 largest unfavorable revenue variances and the 2 largest favorable
      ones, with region, product line, and variance %.
   2) Flag any anomalies: variances at or beyond +/-15%, gross-margin drops of 8 points
      or more, and any blank/missing actuals.
   3) For each flagged item, suggest one question I should ask before I trust it.
   End with the assumptions you made and which numbers you could not verify.
   ```

> **Model note:** if the reasoning looks shallow or the math seems off, switch to a **more
> capable model** in Copilot Chat and re-run. Finance analysis is a good case for the
> stronger reasoning model.

### Task 3 — Spot-check the flags before you trust them (6 min)

1. Go back to the spreadsheet and verify **two** flagged rows by hand. Confirm the
   missing-actual row and the large Midwest miss both show up.
2. Then make Copilot show its work:

   ```
   For the three unfavorable variances you flagged, show the exact budget figure, actual
   figure, and the arithmetic you used for each variance %. If any figure came from a
   blank or inferred value, say so explicitly.
   ```

3. If the arithmetic doesn't reconcile to the sheet, that's your finding — not Copilot's.

### Validation checkpoint (6 min)

In a scratch doc, answer for this analysis:

- **Source:** Which file/tab did Copilot use? Any row it couldn't read?
- **Assumptions:** How did it treat the blank actual? Did it annualize or assume anything?
- **Risk:** What's the cost if a flagged variance is wrong — or a real one is missed?
- **Human check:** Who confirms these numbers before they reach the CFO?

> **Exercise 1 output:** a variance and anomaly list with the arithmetic spot-checked and
> every unverifiable figure labeled.

# Exercise 2 — QA the data, then write for leadership (about 30 min)

**Scenario:** Before anything goes to Dana, you need to clean a messy AR aging sheet, then
turn your findings into a one-page memo and a single leadership slide — in her voice, not
yours.

### Task 1 — Spreadsheet QA on a messy sheet (8 min)

1. Open `AcmeBottling_Finance_AR_Aging.xlsx` in **Excel** (the *AR Aging* tab).
2. With **Copilot in Excel**, run a QA pass:

   ```
   Review this AR aging sheet for data-quality problems ONLY within this file. Check for:
   inconsistent or invalid date formats, aging buckets that don't match Days Past Due,
   negative or zero amounts, blank Days Past Due, status typos, and possible duplicate
   invoices. Return a table: row, field, the issue, and the suggested fix. Do not change
   the data — just list the problems.
   ```

3. Confirm Copilot catches the big ones: the bad date format, the mis-bucketed 90+ invoice,
   the negative amount, the blank/negative days-past-due, and the status typo.

> **Why:** "Do not change the data" is the control. Copilot proposes; you decide what gets
> corrected and by whom.

### Task 2 — Draft the finance memo in Word (8 min)

1. Open `AcmeBottling_Leadership_Audience_Profile.docx` and `AcmeBottling_Executive_Memo_Format.docx` — read who
   you're writing for and the structure to match.
2. In **Copilot in Word**, generate the memo:

   ```
   Draft a one-page finance executive memo for the audience described below, using my
   variance findings and QA notes. Follow this structure exactly: 1) Bottom line
   (2–3 sentences), 2) Variance highlights (table: area, budget vs actual, driver,
   confidence), 3) Margin notes, 4) Anomalies & data-quality flags, 5) Assumptions &
   what a human must verify, 6) Recommended next step. Label every unconfirmed number as
   "estimate pending review." Audience: [PASTE FROM PROFILE]. Findings: [PASTE].
   ```

3. Tighten the Bottom Line so it leads with the single decision Dana must make.

### Task 3 — Build the one-slide leadership summary (6 min)

1. Open **PowerPoint**, start a blank deck, open **Copilot in PowerPoint**:

   ```
   Create ONE executive summary slide from the memo I paste below. Title = the headline
   decision. Include: 3 bullets max (biggest driver, margin note, top anomaly), and a
   one-line "what we need from you." Keep it plain and board-ready. Memo: [PASTE]
   ```

2. Check that nothing on the slide is an unverified figure presented as fact — if it is,
   label it as an estimate.

### Task 4 — Save your prompt library (3 min)

Create a Word doc titled **"Acme Finance — Prompt Library"** and paste in the four prompts
from the [Prompt Library](#prompt-library-your-leave-behind) section below.

This is your leave-behind. Swap in next month's file and the same controls apply.

### Validation checkpoint (5 min)

- **Source:** Did the memo and slide use only your analysis and QA notes, or did Copilot
  reach outside them?
- **Assumptions:** Is every estimate labeled "estimate pending review"?
- **Risk:** What's the cost if an unverified figure lands in front of the CFO as fact?
- **Human check:** Who signs off on the memo before Dana sees it?

> **Exercise 2 output:** a data-quality findings list, a one-page memo, a leadership slide,
> and a 4-prompt library.

## Facilitator notes

- **Data hygiene:** Ex.2 Task 1's "do not change the data" instruction is the teachable
  habit — Copilot proposes corrections, a person applies them.
- **Finance reality:** Reinforce that Copilot does not replace financial judgment. The
  Ex.1 Task 3 show-your-arithmetic step is the moment this lands — if the math doesn't
  reconcile to the sheet, the participant just caught it, and that's the whole point.
- **Capture agent ideas:** If someone says "I want an agent that reconciles the ledger" or
  "auto-close," that's a real agent opportunity — capture it and route to **Chris
  Bartlow**. Keep this lab current-state Copilot.
- **Timing:** Fast groups can rerun the Ex.1 analysis with the threshold changed to
  +/-10% to prove the prompt template is genuinely reusable, or bring in the YTD tab.

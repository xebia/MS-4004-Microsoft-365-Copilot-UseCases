# MS-4004.X — Design & Engineering Hands-On Lab
### Acme Bottling · Microsoft 365 Copilot

**Audience:** Design and engineering team members who already use Copilot and want to pull clear insight from imperfect CRM and opportunity data.

**Format:** ~65 minutes of hands-on

**Level:** Intermediate. We skip the basics and get straight into real Acme Bottling work.

You'll take an opportunity/CRM export — messy, like the real thing — find aging deals and trends, force the data-quality gaps into the open, and write a leadership summary that states what it can't prove.

> **How to use this lab:** Just read and follow along. Nothing to install, no repo to download, no code to save. Open the files linked below and go.

---

## What you'll be able to do

- Analyze an opportunity export for stale deals, aging, and missing statuses.
- Calculate pipeline metrics — win rate, open value, weighted forecast — and keep the
  assumption behind any forecast yours, stated, and visible.
- Identify trends by segment, region, product type, or owner.
- Make Copilot flag data-quality gaps instead of quietly filling them.
- Chart a result without letting a two-record column look like a two-hundred-record one.
- Write a leadership summary with clear findings, risks, and stated assumptions.
- Build reusable prompts for data-quality review, aging, metrics, trends, and summaries.
- Keep a validation habit so no trend reaches leadership with more confidence than it earned.

## Learning arc

This lab moves in one direction: **find the truth, then act on it.**

|  | **Exercise 1 — Find what's aging and what's missing** | **Exercise 2 — Turn analysis into a leadership summary** |
|---|---|---|
| **You're doing** | Reading a messy CRM export and computing from it | Packaging findings for a decision |
| **Copilot's job** | Summarize, age, calculate, chart, flag gaps | Draft to a structure, state its limits |
| **Your job** | Decide which trends the data can support — and supply the assumptions it can't | Decide how much confidence to claim |
| **Stakes** | Internal — only you see it | External — leadership acts on it |
| **You leave with** | An aging list, computed metrics, and an honest gap list | A summary, a slide, and a 5-prompt library |

Every task runs the same beat: **prompt → read it critically → keep what's reusable.**
Every exercise ends the same way: **Source / Assumptions / Risk / Human check.**

# Exercise 1 — Find what's aging and what's missing

**Objective:** Produce a ranked list of stalling opportunities, a set of pipeline metrics
whose assumptions are yours and stated, and an explicit list of the data gaps that limit
what you're allowed to claim.

**Scenario:** Leadership wants to know which opportunities are stalling and whether the
pipeline data can even be trusted. Start there.

### Task 1 — Set your analysis voice and get a clean read

First you'll tell Copilot how to handle incomplete data, then get an overview of the export.

1. Open **Copilot Chat** and go to **Settings** (gear icon or your profile picture, top
   right) → **Personalization**.
2. Add this **custom instruction** and save:

   ```
   When I analyze pipeline or CRM data: never fill in a missing value — flag it. Say how
   many rows a conclusion is based on, and tell me when a trend is too thin to trust.
   End with the assumptions you made and what I should verify.
   ```

   *No Personalization option in your tenant? Paste this block at the top of your first
   prompt in each exercise instead.*
3. Open `AcmeBottling_Opportunities.xlsx` in **Excel** — press **Start** and type *Excel*,
   or use the app launcher (the grid icon, top-left) in Microsoft 365 on the web.
4. Click anywhere in the data and press **Ctrl+T** to format it as a table (accept the
   defaults). Copilot in Excel works far better on a real table than on a loose range.
5. On the **Home** tab, click the **Copilot** button (lower right corner or right of the
   ribbon), then paste:

   ```
   Review this opportunity export. Give me a plain-English summary: total opportunities,
   how many in each Stage, and how many rows are missing a Stage, LastActivityDate, or
   EstValueUSD. List the incomplete rows by OpportunityID. Do not guess or fill in missing
   values — just flag them.
   ```

6. Note how Copilot surfaces the gaps rather than papering over them.

> **Why this matters:** You're establishing how much of this pipeline is actually
> knowable before you let anyone draw a conclusion from it.

### Task 2 — Find the aging opportunities

"Aging" is two different questions wearing one word: *how old is the record* and *how long
has nobody touched it*. The prompt asks for both, then forces a ranking — because a sorted
list is data and a top three is a decision.

1. **Stay in the same Excel Copilot pane** and paste:

   ```
   Identify the opportunities most at risk of going stale: those with the highest AgeDays
   or no recent LastActivityDate, excluding any marked Won or Lost. Show OpportunityID,
   CustomerID, Stage, AgeDays, EstValueUSD, and Owner, sorted by age. Which owner has the
   most aging deals?
   ```

   *If Copilot asks what counts as "no recent activity," say **more than 60 days ago or
   blank**. The file doesn't define "stale" — that threshold is your assumption, so make it
   visible. 30 days flags three-quarters of the pipeline and tells you nothing.*

2. **Stay in the same Excel Copilot pane** and make Copilot commit to a priority:

   ```
   Of these, which three would you chase first and why? Weigh estimated value against how
   long they've been silent. Say which ones you can't rank because data is missing.
   ```

### Task 3 — Compute the numbers, then chart them

Counting and sorting isn't analysis yet. This task makes Copilot *calculate* — and it's built
around a trap. This export has no probability column, so if you ask for a weighted forecast,
the weights have to come from somewhere. If they don't come from you, Copilot invents them,
and the forecast looks equally authoritative either way.

1. **Stay in the same Excel Copilot pane** and start with the arithmetic that needs no
   assumptions:

   ```
   Using only this table, calculate three things and show the formula for each: (1) win
   rate, counting Won against Won plus Lost only, (2) total open pipeline value, excluding
   Won, Lost, and any row with a blank Stage or blank EstValueUSD, and (3) average AgeDays
   by Stage. For each figure, tell me how many rows it is based on and how many rows you
   excluded and why. Do not estimate any value that is blank.
   ```

2. Verify one of the three by hand against the sheet. If the included and excluded rows
   don't add back up to the rows in the file, that difference is your data-quality story —
   not a rounding error.
3. Now the trap. **Stay in the same pane** and ask for a forecast, supplying the assumption
   yourself:

   ```
   Now build a weighted pipeline forecast using these stage probabilities, which are my
   assumptions and are not in the data: Qualifying 10%, Proposal 30%, Negotiation 60%, On
   Hold 5%. Show the weighted value per stage and the total. State at the top that the
   weights were supplied by me and are not derived from this file, and list any stage you
   found in the data that I did not give you a weight for.
   ```

4. **Now ask the same question without the weights.** In the same pane, paste only:

```
Build a weighted pipeline forecast from this data.
```

Compare the two answers. If the
   second one produced a confident total, go looking for where its percentages came from —
   they are not in the file. **A forecast is only as real as the assumption under it, and
   the assumption has to be yours and visible.**
5. Make it a chart:

   ```
   Add a column chart of open pipeline value by Stage, excluding Won and Lost, titled for a
   leadership audience. Include the row count each column is based on in the axis labels or
   the chart title.
   ```

6. Look at the chart against those row counts. A tall column resting on two opportunities is
   exactly the thing this lab exists to catch.

> **Why this matters:** A chart is the most persuasive object in a review and the least
> interrogated. Putting the denominator into the chart itself is a small habit that stops a
> three-record column from carrying the same visual weight as a thirty-record one.

### Task 4 — Spot the trends

This is where the lab's real lesson lands. A trend drawn from eleven rows reads exactly like
a trend drawn from eleven hundred — same confident sentence, same clean grouping. The one
phrase that changes that is **"say how many rows it's based on."**

1. Open `AcmeBottling_Master_Reference.xlsx` in **Excel** and look at the **Customers**
   and **Products** tabs for segments and product categories. You're only reading this one —
   if it opens without a Copilot button, that's fine here, keep going.
2. Open **Copilot Chat**, attach `AcmeBottling_Opportunities.xlsx` with the paperclip
   icon, and paste:

   ```
   Help me find trends in this pipeline. Group opportunities by customer segment (Brewery,
   Juice, Water, Kombucha, Soda, Spirits, Coffee) and by product category (Glass, PET,
   Closure). Where is value concentrated, and where are deals stalling? For each trend,
   say how many rows it's based on and note where missing data limits the analysis.
   ```

3. Read the trends and note where gaps weaken the conclusions.
4. **Save your findings so Exercise 2 can read them.** Open **Word** — press **Start** and
   type *Word*, or use the app launcher (the grid icon, top-left) in Microsoft 365 on the
   web — choose **Blank document**, copy your aging list, computed metrics (including the
   stated forecast assumptions), trends, and data-quality gaps out of the chat and paste them
   in, then **Create a copy → Create a copy online** → your **`Acme - Pipeline Review Q3`**
   folder → name it **`Pipeline Findings`**.

> **Why this one save matters:** Copilot's context stops at the app boundary — Word and
> PowerPoint can't see this chat. A file in your lab folder they can both read. From here on
> you'll point Copilot at the findings instead of re-pasting them, which is the habit worth
> taking back to work.

### Validation checkpoint

- **Source:** Which file(s) did Copilot use? Did it stay inside them?
- **Assumptions:** Did it fill any blank Stage or value? Did it call a trend from thin data?
  Whose stage probabilities ended up in the forecast — yours, or ones it made up?
- **Risk:** What goes wrong if leadership acts on a trend built on incomplete rows, or on a
  forecast whose weights nobody owns?
- **Human check:** Which 2–3 opportunities will you verify in the CRM before reporting?

> **Exercise 1 output:** an aging list ranked by value and silence, a set of computed
> pipeline metrics with their row counts and stated assumptions, a chart that carries its own
> denominator, and an explicit list of the gaps that limit what you can claim.

# Exercise 2 — Turn analysis into a leadership summary

**Objective:** Package the findings into a one-page summary and a single slide that keep
their uncertainty visible instead of rounding it away.

**Scenario:** Now package it. Leadership wants a short, honest read — findings, risks, and
what to fix in the data.

### Task 1 — Keep your context clean

Everything after this point is something leadership acts on. Narrow the ground Copilot is
standing on before you generate a word of it.

1. In **Copilot Chat**, start a **New chat** (the pencil or **New chat** icon at the top
   of the pane) so Copilot references only this review's material.
2. Confirm the opportunity export and the reference workbook are both in your
   **`Acme - Pipeline Review Q3`** folder.

> **Why:** One folder, one clean chat per review keeps the analysis scoped and trustworthy.

### Task 2 — Draft the leadership summary in Word

The `/` reference is how this pane gets your findings — it can't see the chat you ran them
in. Watch the "Data-quality gaps" section especially: summarizing is compression, and
uncertainty is the first thing compression drops.

1. Open **Word** — press **Start** and type *Word*, or use the app launcher (the grid icon,
   top-left) in Microsoft 365 on the web. Choose **Blank document**, then **Create a copy →
   Create a copy online** → your **`Acme - Pipeline Review Q3`** folder → name it
   **`Pipeline Leadership Summary`**.
2. On the **Home** tab, click the **Copilot** button (lower right corner or right of the
   ribbon). In the prompt box type **`/`** and pick **Pipeline Findings**, then add:

   ```
   From the referenced findings, write a one-page leadership summary of this pipeline
   review. Structure it as: Headline findings, Aging risk (which deals and owners), Trends
   by segment and product, Data-quality gaps that limit confidence, and Recommended
   actions. Keep it under 300 words, plain English, no filler. End with an "Assumptions &
   to verify" line listing the data gaps.
   ```

3. **Where the answer lands depends on your version of Word.** Some builds draft straight
   into the document — if so, review it and click **Keep it** (or **Regenerate** /
   **Discard**). If the answer stays in the Copilot pane instead, click **Insert** under the
   response, or **Copy** and paste it into the page. Either way, nothing is final until you
   accept it.
4. Review. Confirm the assumptions/data-gap line is present and honest, then **save**.

### Task 3 — Build one summary slide in PowerPoint

One page compressed to one slide. Same risk as Task 2, doubled: a bullet has no room for a
caveat, so a hedged finding either survives as its own line or quietly becomes a fact.

1. Open **PowerPoint** — press **Start** and type *PowerPoint*, or use the app launcher
   (the grid icon, top-left) in Microsoft 365 on the web. Choose **Create Blank
   Presentation**, then **Create a copy → Create a copy online** → your
   **`Acme - Pipeline Review Q3`** folder → name it **`Pipeline Review Slide`**.
2. On the **Home** tab, click the **Copilot** button (lower right corner or right of the
   ribbon). In the prompt box type **`/`** and pick **Pipeline Leadership Summary**, then
   add:

   ```
   Create a single executive summary slide from the referenced leadership summary: a clear
   headline, 3-4 bullet findings, one line on data-quality risk, and one recommended next
   step. Tight text, no paragraphs, no stock images. Do not state a trend as fact if the
   summary labeled it uncertain.
   ```

3. Tighten to one clean slide, and check the data-quality line survived the compression.

> **Two documents, no copy-paste.** You wrote the findings once and referenced them from
> Word, then referenced the summary from PowerPoint. That's the whole reason the folder rule
> exists.

### Task 4 — Save your prompt library

This quarter's pipeline is this quarter's. The prompts are for every review after it.

1. Create a new **Word** doc titled **"Acme Design & Engineering — Prompt Library"**.
2. Paste in the five prompts from the
   [Prompt Library](#prompt-library-your-leave-behind) section below.
3. Save it somewhere you'll actually find it again.

This is your leave-behind. Swap in next quarter's export and reuse.

### Validation checkpoint

- **Source:** Did the summary and slide stay inside the export and reference data?
- **Assumptions:** Did Copilot state its data gaps, or imply more certainty than the data supports?
- **Risk:** What's the cost of presenting a confident trend built on missing rows?
- **Human check:** Who validates the numbers before this reaches leadership?

> **Exercise 2 output:** a one-page leadership summary, a single executive slide that
> keeps its uncertainty, and a 5-prompt library.

## Prompt Library (your leave-behind)

Save these five. Anything in `[BRACKETS]` is a blank you fill in — delete the brackets too.
If you're stuck on one, use what you did in this lab: `[SOURCE FILE]` →
*AcmeBottling_Opportunities.xlsx*, `[AGE FIELD]` → *AgeDays*, `[ACTIVITY FIELD]` →
*LastActivityDate*, `[DIMENSION 1]` → *customer segment*. Where it says **PASTE**, paste the
actual text in.

**1. Data-quality review**
```
Review [SOURCE FILE]. Give me row counts by [STATUS FIELD — e.g. Stage] and list every row
missing [REQUIRED FIELDS — e.g. Stage, LastActivityDate, EstValueUSD], by [ID FIELD — e.g.
OpportunityID]. Do not guess or fill in missing values — flag them.
```
*Run this one first, every time. You can't judge a trend until you know how much of the file
is actually readable.*

**2. Aging / stale-record analysis**
```
From [SOURCE FILE], identify the records most at risk of going stale: highest [AGE FIELD]
or no recent [ACTIVITY FIELD], excluding [CLOSED VALUES — e.g. Won or Lost]. Show
[FIELDS TO DISPLAY], sorted by age. Then rank the top [N] to chase, weighing
[WHAT YOU RANK ON — e.g. estimated value against time silent], and say which you can't rank
because data is missing.
```
*Two dials: what you exclude, and what you weigh. Change either and the top three changes —
which is how you check whether the ranking was ever real.*

**3. Computed metrics, forecast, and chart (assumptions stated)**
```
Using only [SOURCE FILE], calculate and show the formula for each: [THE METRICS YOU NEED —
e.g. win rate counting Won against Won plus Lost only, total open value, average age by
stage]. Exclude [WHAT DOESN'T COUNT] and any row with a blank [REQUIRED FIELDS]. For each
figure, tell me how many rows it is based on and how many you excluded and why. Do not
estimate any blank value.
Then build a weighted forecast using these weights, which are my assumptions and are not in
the data: [YOUR WEIGHTS]. State at the top that the weights are mine and not derived from
the file, and list any category you found that I did not give a weight for.
Then add a [CHART TYPE] of [MEASURE] by [DIMENSION], titled for [AUDIENCE], with the row
count each column is based on shown in the labels or title.
```
*Supply the weights or Copilot will. Nothing in a CRM export says what a Proposal is worth,
so an unweighted "weighted forecast" is a number with an invisible author. Putting row counts
in the chart is the same idea applied to the most persuasive object in the room.*

**4. Trend analysis**
```
Find trends in [SOURCE FILE]. Group by [DIMENSION 1 — e.g. customer segment] and
[DIMENSION 2 — e.g. product category]. Where is value concentrated and where are records
stalling? For each trend, say how many rows it's based on and where missing data limits the
analysis.
```
*"Say how many rows it's based on" is the entire prompt. Without the denominator, a trend
from three records reads like a trend from three hundred.*

**5. Leadership summary**
```
Write a one-page leadership summary of this review. Structure: Headline findings, Risk,
Trends, Data-quality gaps that limit confidence, Recommended actions. Under [WORD COUNT],
plain English. Do not state a trend as fact if the findings labeled it uncertain. End with
an "Assumptions & to verify" line listing the data gaps. Findings: [PASTE FINDINGS HERE]
```
*Or, if you saved your findings as a file, reference it with `/` in Word and drop the last
line. That's the version that scales.*
